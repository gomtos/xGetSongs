# Qt 전환 Q4: 화면, 플레이리스트, 정보 창 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development를 **가볍게** 쓴다(사용자 지시 2026-11-25): 작업은 4개, 작업 리뷰는 작업 1(스레드·종료 순서)에만 두고, 전체 최종 리뷰는 돌리기 전에 사용자에게 묻는다. 뺀 검증은 보고서의 "확인하지 못한 것"에 적는다.

**Goal:** `qt/app`에 Qt Widgets 화면을 만들어, 지금 Tauri 화면이 하는 일(도구 상태, 조회, 다운로드, 취소, 재시도, 설정)과 자체 플레이리스트(설계 §5), 정보 창(설계 §6)을 가진 `xGetSongs.exe`가 뜨게 한다.

**Architecture:** 화면 로직은 위젯 없는 정적 라이브러리 `xgsui`(Qt Core·Network)에 두고 Qt Test로 시험한다. `AppStateHolder`는 지금 TS `state/holder.ts`를 옮긴 것으로 GUI 스레드에서만 돌고, 엔진은 `AppApi` 인터페이스 뒤에 둔다. 진짜 구현 `EngineApi`가 `qt/core`의 막는 호출을 `std::jthread`에서 돌리고 결과를 큐에 넣은 호출로 GUI 스레드에 넘긴다. 위젯(`qt/app`)은 상태를 그리기만 한다.

**Tech Stack:** C++20, Qt 6.11.3 정적(Core, Gui, Widgets, Network, Test), WebView2(`xgswebview`), MSVC, CMake + Ninja.

**Spec:** `docs/superpowers/specs/2026-11-15-qt-rewrite-and-playlists-design.md` (§3 호환, §4 Q4, §5, §6, §7), 분석 문서 `docs/superpowers/specs/2026-11-06-qt-cpp-rewrite-analysis.md` §7 Q4 행. 넘겨받은 일: `2026-11-21-qt-engine-job-report.md`의 "Q3·Q4에 넘길 것", `2026-11-21-qt-google-lyrics-report.md`의 Q4 항목.

## Global Constraints

- Q3의 규칙이 그대로다(`.superpowers/sdd/2026-11-21-qt-google-lyrics/common-rules.md`): JDK·kotlinx 소스를 보지 않는다, `qt/`만 바꾼다(`qt/spike` 제외), Gradle을 돌리지 않는다, 실행 중인 xGetSongs와 `%APPDATA%\xGetSongs`·`%LOCALAPPDATA%`의 앱 폴더를 건드리지 않는다, 두 빌드 경고 0, `main`에 한국어 커밋, push하지 않는다.
- **네트워크 없음.** 시험은 `127.0.0.1`과 가짜 응답만 쓴다. `www.gtcsoft.kr`, 구글, lrclib.net, YouTube를 부르지 않는다. 내려받기 없음.
- **화면에 아무것도 띄우지 않는다.** 위젯 시험은 `QT_QPA_PLATFORM=offscreen`으로만 돌린다. 실제 창을 띄우는 확인은 작업 4에서 controller가 사용자에게 알린 뒤 한 번만 한다.
- 시험과 점검은 가짜 `APPDATA`·`LOCALAPPDATA`(`QTemporaryDir`)와 별도 단일 인스턴스 식별자를 쓴다. 제품 식별자는 지금 Tauri 판과 같게 한다(설계 §3).
- 설정은 `%APPDATA%\xGetSongs\settings.json`을 같은 형식(`outputDir`, `overwrite`, `includeRank`, `searchLyricsOnline`)으로 읽고 쓰며 모르는 키를 지우지 않는다. 쓰기는 `QSaveFile`.
- 지금 화면에 없는 기능은 만들지 않는다(곡별 취소, 트레이, 창 위치 저장, 닫기 확인 없음). 더하는 것은 설계 §5와 §6뿐이다.
- 가사와 실제 곡 이름을 출력·로그·커밋에 남기지 않는다. 시험 문구는 지어낸 것.

## Review Focus

1. 다운로드 중 창 닫기: 5초 안에 자손까지 끝나고 프로세스가 남지 않는다(숨은 WebView2 창이 앱을 살려 두지 않는다). → 작업 1 `closingWhileAJobRunsEndsEverything`, 작업 3 종료 순서.
2. 멈춘 뒤 늦게 온 답(조회 결과, 도구 상태, 이벤트)이 화면 상태를 바꾸지 않는다. → 작업 1 `anAnswerAfterStopIsDropped`.
3. `playlists.json`이 깨졌거나 쓰는 중 실패해도 사용자의 목록을 잃지 않는다. → 작업 2 `aBrokenFileIsKeptAsBad`, `aFailedWriteLeavesTheOldFile`.
4. 원격 목록의 나쁜 값(긴 이름, 제어 문자, `http://` URL, 1MB 넘는 응답)이 목록에 들어가지 않는다. → 작업 2.
5. 한글 조합 중 입력란을 다시 쓰지 않는다(순위 번호 칸의 숫자 거르기 포함). → 작업 3, 사용자가 직접 확인.

### Task 3: 위젯 화면과 앱 조립 (`qt/app`)

**Files:**
- Create: `qt/app/{CMakeLists.txt, main.cpp, app_services.{h,cpp}, main_window.{h,cpp}, playlists_dialog.{h,cpp}, playlist_entry_dialog.{h,cpp}, about_dialog.{h,cpp}, single_instance.{h,cpp}, app.qss, app.qrc}`, `THIRD-PARTY-NOTICES`, `qt/tests/app/{tst_main_window.cpp, tst_playlists_dialog.cpp, tst_single_instance.cpp}`
- Modify: `qt/CMakeLists.txt`(`Widgets`), `qt/README.md`

**Interfaces:**
- `class AppServices`: 진짜 부품을 만들고 순서대로 없앤다. 가사는 설명란 → LRCLIB → 구글(`FallbackLyricsProvider`), 구글 공급자·채널·`LyricsBrowser`는 하나를 같이 쓴다. `LyricsBrowser`는 GUI 스레드에서 만들고 없앤다. WebView2 사용자 데이터 폴더 `%LOCALAPPDATA%\xGetSongs\qt-webview2`, `tempRoot`는 출력 폴더와 같은 드라이브. HTTP 클라이언트는 하나. 동시 수는 `automaticConcurrency()`.
- `class MainWindow : public QMainWindow`: `AppStateHolder::changed`에 맞춰 다시 그린다. 요소와 켜짐 조건은 `shell/index.html`·`shell/src/main.ts`와 같다(도구 카드, 입력 줄, 오류 띠, 조회 결과, 옵션, 목록, 단계별 버튼). 더하는 것: 입력란 왼쪽 `플레이리스트 ▾`(§5.2), 정보 창을 여는 버튼. 창 1000×760, 제목 `xGetSongs`. 닫을 때 `flush()` 뒤 `AppServices`를 내린다.
- `class SingleInstance { public: explicit SingleInstance(QString id); bool isFirst() const; void onSecondLaunch(std::function<void()>); };` 두 번째 실행은 첫 창을 앞으로 가져오고 끝난다. 제품 `id`는 Tauri 판과 서로를 알아보는 값이어야 한다: `tauri-plugin-single-instance`(MIT/Apache-2.0)가 Windows에서 쓰는 이름 규칙을 그 문서나 소스에서 확인해 맞춘다. 맞출 수 없으면 그 사실을 보고하고 Qt 판끼리만 막는다.
- `AboutDialog`: §6의 내용. 버전은 CMake `PROJECT_VERSION`, Qt 버전은 `qVersion()`.
- WebView2 런타임이 없으면 앱은 그대로 뜨고 구글 가사만 빠진다(로그 한 줄). 알림 상자는 띄우지 않는다.
