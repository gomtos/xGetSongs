# Qt 전환 Q0 스파이크 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 정적 링크한 Qt 6 Widgets exe 하나로 분석 문서 §9의 관문 Q1~Q8을 재서, C++/Qt 전면 재작성을 계속할지 정할 근거를 만든다.

**Architecture:** 저장소 밖의 vcpkg로 정적 Qt와 WebView2 SDK를 빌드하고, `qt/spike/`에 버리는 코드로 작은 Widgets exe를 만든다. exe는 명령줄 스위치마다 점검 하나를 돌리고 결과를 JSON 파일로 남기며, PowerShell 스크립트가 가짜 깨끗한 PC 환경에서 exe를 돌려 값을 모은다. 사람이 봐야 하는 것(한글 입력, 배율, SmartScreen)은 마지막에 사용자가 본다.

**Tech Stack:** C++20, Qt 6 (Core, Gui, Widgets, Network) 정적 링크, WebView2 SDK(정적 로더), MSVC(Visual Studio 2022), CMake + Ninja, vcpkg(triplet `x64-windows-static`), PowerShell 7.

**Spec:** [docs/superpowers/specs/2026-11-15-qt-rewrite-and-playlists-design.md](../specs/2026-11-15-qt-rewrite-and-playlists-design.md) §3, §4. 관문의 정의는 [분석 문서](../specs/2026-11-06-qt-cpp-rewrite-analysis.md) §9.

## Global Constraints

- 스파이크 코드는 버리는 코드다. `qt/spike/` 밖의 제품 코드(Kotlin·Rust·TS, Gradle·Cargo·npm 설정)는 한 줄도 바꾸지 않는다.
- Qt 모듈은 Core, Gui, Widgets, Network만 쓴다. TLS는 Schannel이고 OpenSSL을 넣지 않는다. QtWebEngine과 GPL 전용 모듈은 쓰지 않는다.
- 링크는 Qt와 CRT 모두 정적(`x64-windows-static`, `/MT`). exe 하나만 나온다. UPX 같은 실행 압축기는 쓰지 않는다.
- Qt 버전은 Task 1을 시작할 때의 최신 vcpkg 기준선이 주는 Qt 6.x이고 `builtin-baseline`으로 고정한다. LTS가 아니어도 된다.
- vcpkg는 저장소 밖 `C:\dev\vcpkg`에 둔다. CMake 빌드 폴더는 `build/qt-spike`(이미 `.gitignore`의 `build/` 안).
- 점검은 사용자가 실행 중인 xGetSongs를 건드리지 않는다: `APPDATA`·`LOCALAPPDATA`·`TEMP`는 `%TEMP%\xgs-qt-spike-<id>` 아래의 빈 폴더(이름에 한글과 공백을 넣는다: `로컬 폴더`, `로밍 폴더`), 창 제목과 실행 파일 이름은 `xgs-qt-spike`이며 `xGetSongs`의 단일 인스턴스 잠금·설정·로그 경로를 쓰지 않는다. 점검이 끝나면 자기 폴더를 지운다.
- 화면에 창이 뜨는 점검(Task 3의 시작 시간 측정, Task 6)은 돌리기 전에 사용자에게 한 줄로 알린다.
- Q4(Defender), Q5(자손 정리), Q6(한글 입력·배율) 중 하나라도 실패하면 **멈추고 사용자에게 알린다.** Q4의 실패는 Defender가 exe를 격리·삭제·실행 차단하는 것이다. SmartScreen의 "알 수 없는 게시자" 경고는 지금 exe와 나란히 비교해 지금보다 나쁘지 않으면 통과다.
- 구글은 부르지 않는다. 외부로 나가는 요청은 Task 5의 `https://lrclib.net` 1회와 Task 4의 yt-dlp 조회뿐이다.
- 커밋은 `main`에 직접, 메시지는 한국어, 끝에 `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`. push는 하지 않는다(사용자에게 묻는다).
- Gradle은 이 계획에서 돌리지 않는다.

## Review Focus

스파이크라서 단위 시험은 없고 점검 스크립트가 시험이다. 아래는 점검이 놓치기 쉬운 조건이고, 각 줄 끝의 Task가 그 조건을 점검에 넣는다.

1. exe가 한글·공백이 든 폴더에 있고 `APPDATA`도 한글·공백 경로일 때 창이 뜬다 → Task 3 (`내 앱 폴더`에 복사해 돌린다).
2. yt-dlp가 PATH에 없을 때 자손 정리 점검이 "실패"가 아니라 "건너뜀"으로 남고, 도구가 필요 없는 `cmd → ping` 시나리오는 그래도 돈다 → Task 4.
3. 스파이크 exe 자신이 강제 종료될 때(`Stop-Process -Force`)도 자손이 남지 않는다(취소 버튼 경로만 보면 놓친다) → Task 4.
4. WebView2 런타임이 없는 것처럼 보일 때(환경 생성 실패) exe가 죽지 않고 `"webview": {"ok": false, "error": …}`를 남긴다 → Task 5.
5. 측정이 백신의 첫 검사 시간을 "두 번째 실행"에 섞지 않는다: 첫 실행은 새로 복사한 exe, 두 번째는 같은 파일 → Task 3.

**exe의 명령줄 (모든 Task가 공유하는 계약)**

```
xgs-qt-spike.exe [--report <파일>] [스위치 하나]
  (스위치 없음)            창을 띄우고 사용자가 닫을 때까지 둔다 (Task 6)
  --exit-after-show        창이 처음 그려지고 이벤트 루프가 한가해지면 "start"를 쓰고 끝낸다
  --spawn-tree <초>        cmd /c "ping -n <초> 127.0.0.1"을 Job에 넣어 띄우고 "spawned"를 쓴 뒤 창을 유지한다
  --spawn-cmd <명령줄>     주어진 명령을 Job에 넣어 띄운다 (yt-dlp용). 나머지는 --spawn-tree와 같다
  --cancel-after <ms>      --spawn-* 와 함께: <ms> 뒤에 취소(Job 종료)하고 "cancelled"를 쓰고 끝낸다
  --webview-check <URL>    숨긴 WebView2로 URL을 열고 "webview"를 쓰고 끝낸다
  --tls-check              lrclib.net을 부르고 "tls"를 쓰고 끝낸다
```

`--report`가 없으면 결과를 쓰지 않는다. 결과 파일은 UTF-8 JSON 객체 하나이고 스위치마다 최상위 키 하나를 더한다(각 Task에 형식).

### Task 4: 자손 프로세스 정리 (Q5, 멈춤 관문)

**Files:**
- Create: `qt/spike/src/job_process.h`, `qt/spike/src/job_process.cpp`, `qt/spike/check/descendants.ps1`
- Modify: `qt/spike/src/main.cpp`, `qt/spike/CMakeLists.txt`

**Interfaces:**
- Produces:
  ```cpp
  class JobProcess : public QObject {
  public:
      explicit JobProcess(QObject* parent = nullptr);   // Job Object를 만든다: JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE
      bool start(const QString& program, const QStringList& arguments);  // 자식이 한 줄도 실행하기 전에 Job에 넣는다
      void cancel();                                    // TerminateJobObject: 자식과 자손을 모두 끝낸다
      qint64 processId() const;
  signals:
      void finished(int exitCode);
  };
  ```
  "자식이 실행하기 전에 Job에 넣는다"는 `QProcess::setCreateProcessArgumentsModifier`로 `CREATE_SUSPENDED`를 주고, `started` 뒤 `AssignProcessToJobObject` → `ResumeThread`로 한다(스레드 핸들은 modifier가 받는 `PROCESS_INFORMATION`이 아니라 시작 뒤에는 얻기 어려우니, 안 되면 `CreateProcessW`를 직접 부르고 출력만 파이프로 읽는다. 어느 쪽이 됐는지 보고서에 적는다).
- Produces: `"spawned": {"pid": <자식 pid>}`, `"cancelled": {"afterMs": <ms>}`.

- [ ] **Step 1: `JobProcess`와 `--spawn-tree`, `--spawn-cmd`, `--cancel-after`를 구현한다**
- [ ] **Step 2: `descendants.ps1`을 쓴다**

시나리오 넷. 각 시나리오는 자식 pid에서 `Get-CimInstance Win32_Process`의 `ParentProcessId`를 따라 자손 pid를 모으고, 동작 뒤 100ms 간격으로 살아 있는 수를 세어 0이 될 때까지의 시간을 잰다. **통과: 5초 안에 0, 그리고 2초 뒤에도 0.**

| 시나리오 | 띄우기 | 동작 |
|---|---|---|
| A 취소 | `--spawn-tree 120 --cancel-after 1500` | exe가 스스로 취소 |
| B 강제 종료 | `--spawn-tree 120` | 자손(`PING.EXE`)이 보이면 스파이크를 `Stop-Process -Force` |
| C yt-dlp 취소 | `--spawn-cmd "yt-dlp -J <영상 주소>" --cancel-after 700` | exe가 스스로 취소 |
| D yt-dlp 강제 종료 | `--spawn-cmd "yt-dlp -J <영상 주소>"` | `yt-dlp.exe`가 보이면 스파이크를 `Stop-Process -Force` |

`<영상 주소>`는 `engine/src/integrationTest`의 통합 시험이 쓰는 영상 주소를 쓴다. C와 D는 가짜 PC의 `PATH`에 yt-dlp가 있는 폴더(`Get-Command yt-dlp`, 없으면 `%APPDATA%\xGetSongs` 아래 앱 전용 폴더의 것을 **읽기만** 한다)와 Node가 있는 폴더를 더해 돌리고, yt-dlp를 찾지 못하면 `건너뜀`으로 찍는다(실패가 아니다). 700ms 안에 yt-dlp가 이미 끝났으면 그 회차는 `너무 빨리 끝남`으로 찍고 3번까지 다시 한다.

  창은 화면에 보이지 않는다(부모 HWND는 보이지 않는 최상위 창, 컨트롤러 `put_IsVisible(TRUE)`로 타이머가 돌게 하되 화면 밖 크기 0이 아닌 800×600). InPrivate 프로필, `userDataFolder`는 `LOCALAPPDATA` 아래 `xgs-qt-spike\webview`.

- Produces: `"tls": {"ok": <bool>, "status": <HTTP 상태>, "backend": "<QSslSocket::activeBackend()>", "error": "<있으면>"}`. `--tls-check`는 `GET https://lrclib.net/api/search?track_name=test&artist_name=test`를 15초 제한으로 부른다(개인 정보 없음, User-Agent는 `xgs-qt-spike`).
