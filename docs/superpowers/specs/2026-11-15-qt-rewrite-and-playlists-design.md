# C++/Qt 전면 재작성과 자체 플레이리스트 설계

작성일: 2026-11-15
상태: 사용자 승인 대기
근거: [C++/Qt 전면 재작성(B안) 분석](2026-11-06-qt-cpp-rewrite-analysis.md) (아래에서 "분석 문서")

이 문서에서 "사용자 결정"이라고 적은 것은 사용자가 말한 것이고, "작성자 판단"이라고 적은 것은 이 문서를 쓴 쪽이 정한 것이다. 작성자 판단은 사용자가 뒤집을 수 있다.

## 1. 무엇을, 왜

- **무엇을:** 지금의 xGetSongs(Kotlin 서버 사이드카 + Rust 브리지 + Tauri/TS 화면)를 C++ 한 프로세스(Qt 6 Widgets)로 전부 다시 쓴다(분석 문서의 B안). 그리고 Qt 판에 **자체 플레이리스트**(미리 정해 둔 YouTube 재생목록의 목록) 기능을 더한다.
- **왜 (사용자 결정):** Qt로 옮기기로 정했고, 앱을 **오픈 소스로 공개**한다. 분석 문서 §8의 "지금은 하지 않는다"는 권고는 이 결정으로 대체된다.

분석 문서 §8.1의 조건은 이렇게 정해졌다.

| 조건 | 결정 |
|---|---|
| 웹으로 옮기는 계획 | 접는다. HTTP API와 TS 화면은 없어진다 (B안을 고른 결과) |
| 구글 가사 | **WebView2로 유지한다** (사용자 결정). QtWebEngine은 쓰지 않는다 |
| Qt 라이선스 방식 | LGPLv3, **정적 링크 + 소스 공개** (분석 문서 §6.1) |
| 앱 라이선스 | **MIT** (사용자 결정) |

## 2. 목표, 비목표, 하면 안 되는 것

**목표**

1. 지금 앱이 하는 일을 Qt 판이 똑같이 한다: 입력 판별, 조회, 동시 다운로드와 취소, m4a 태그와 커버, 가사(설명란 → LRCLIB → 구글 가사 카드), 외부 도구 확인과 yt-dlp 설치, 설정 저장, 저장 위치 표시와 탐색기 열기, 단일 인스턴스, 닫기 문턱, 로그와 종료 기록. 동작의 기준은 README와 지금 코드, 그리고 지금 테스트다.
2. `xGetSongs.exe` 하나로 배포한다. 실행에 Java도 풀어 놓는 런타임도 필요 없다.
3. 자체 플레이리스트: 원격 목록으로 초기화(합치기), 추가·수정·삭제, 선택.
4. 오픈 소스로 공개할 수 있는 저장소 상태: `LICENSE`(MIT), Qt 고지, 빌드 방법 문서.

**비목표**

- 웹 이식, macOS·Linux 지원 (Windows 전용 그대로).
- 화면 다시 디자인하기. 화면 구성과 문구는 지금 것을 그대로 옮긴다. 달라지는 것은 플레이리스트 버튼과 대화상자, 정보 창뿐이다.
- 플레이리스트 말고 새 기능.
- 지금의 Tauri 판에 플레이리스트를 넣기 (작성자 판단: Qt 판에만 넣는다).
- 화면 언어 전환. 화면은 한국어만이다.

**하면 안 되는 것**

- Qt 판이 같은 기능을 통과하기 전에 옛 코드(Kotlin·Rust·TS)를 지우는 것. 그 전까지 지금 앱은 그대로 빌드되고 돌아가야 한다.
- 로그에 토큰·가사·제목·파일 이름이 남는 것 (지금의 가리기 규칙을 그대로 지킨다).
- 구글의 CAPTCHA·동의창·429를 우회하는 것 (지금처럼 쉬기만 한다).
- 점검 도구가 사용자가 실행 중인 xGetSongs를 건드리는 것(설정 파일, 단일 인스턴스 잠금, 프로세스). 점검은 가짜 `APPDATA`·`LOCALAPPDATA`와 별도 식별자로 돌린다.
- 원격에서 받은 플레이리스트 내용을 검증 없이 쓰는 것 (§5.5).

## 3. 만드는 방식

| 항목 | 결정 | 누가 |
|---|---|---|
| 언어·UI | C++20, Qt 6 Widgets | 사용자 결정(Qt), 나머지 작성자 판단 |
| Qt 모듈 | Core, Gui, Widgets, Network, Test. TLS는 Schannel(OpenSSL을 넣지 않는다) | 분석 문서 |
| 링크 | 정적 링크(Qt와 CRT 모두), exe 하나. UPX 같은 실행 압축기는 쓰지 않는다 | 분석 문서 + 작성자 판단 |
| Qt 구하기 | vcpkg 매니페스트(`vcpkg.json`)로 이 PC에서 빌드. triplet은 `x64-windows-static`. Qt 버전은 Q0을 시작할 때의 최신 vcpkg 기준선이 주는 Qt 6.x를 쓰고 `builtin-baseline`으로 고정한다. LTS가 아니어도 된다(LTS를 쓰려고 옛 기준선으로 돌아가지 않는다). 고정한 뒤에는 이유 없이 올리지 않는다 | 작성자 판단 |
| 컴파일러·빌드 | Visual Studio 2022(MSVC), CMake + `CMakePresets.json` | 작성자 판단 |
| WebView2 | WebView2 SDK(정적 로더)를 같은 프로세스의 GUI 스레드에서 직접 쓴다 | 사용자 결정 + 분석 문서 |
| 구글 가사 카드 읽기 | 페이지 안에서 스크립트로 줄을 뽑아 온다. HTML 파서 라이브러리는 넣지 않는다 | 작성자 판단 |
| 시험 | Qt Test. 지금 Kotlin·TS 테스트를 같은 이름으로 옮긴다 | 분석 문서 |
| 자손 프로세스 정리 | `QProcess` + Win32 Job Object | 분석 문서 |
| 지원 Windows | Windows 10 이상 (`_WIN32_WINNT=0x0A00`). Qt 6.11이 지원하는 범위 안에서 정한 값이고 사용자가 바꿀 수 있다 | 작성자 판단 |

**저장소 배치 (작성자 판단).** 옮기는 동안 옛 코드와 나란히 둔다.

- `qt/` 아래에 C++ 전부: `qt/core`(화면 없는 로직: 지금의 `shared`·`engine`·`diagnostics`에 해당, Qt Core·Network만 씀), `qt/app`(Widgets 화면과 WebView2), `qt/tests`.
- 화면 로직(상태, 표시 문구, 버튼 활성 조건)은 위젯과 분리해 `qt/core`나 위젯 없는 계층에 두어 Qt Test로 시험한다.
- CMake 빌드 폴더는 `build/qt-*` (이미 `.gitignore`에 있는 `build/` 안).
- 마지막 단계에서 옛 코드를 지운 뒤에도 `qt/`는 그대로 둔다(옮기지 않는다).

**호환 (작성자 판단).** 사용자가 지금 쓰는 것이 그대로 이어져야 한다.

- 설정 파일은 같은 `%APPDATA%\xGetSongs\settings.json`을 같은 형식으로 읽고 쓴다. 모르는 키는 지우지 않는다.
- 앱 전용 폴더에 이미 받아 둔 yt-dlp를 그대로 찾는다.
- 로그 위치와 파일 이름 규칙은 지금과 같게 한다.
- 옮기는 동안 Qt 판과 지금 판은 **같은 단일 인스턴스 식별자**를 쓴다. 둘은 동시에 뜨지 않으므로 같은 설정 파일과 로그 파일에 두 프로세스가 함께 쓰는 일이 없다. 점검 도구만 별도 식별자와 가짜 `APPDATA`·`LOCALAPPDATA`를 쓴다.
- 첫 실행에 `%LOCALAPPDATA%`에 런타임을 푸는 일은 없어진다. 옛 판이 풀어 둔 폴더는 지우지 않는다(README에 손으로 지우는 법만 적는다).

## 4. 단계와 관문

분석 문서 §7의 Q0~Q7과 §9의 스파이크 조건을 그대로 따른다. 앞 단계의 관문을 통과해야 다음으로 간다. 바뀌거나 더해지는 것만 적는다.

| 단계 | 분석 문서와 다른 점 |
|---|---|
| Q0 스파이크 | 빌드 환경(vcpkg, 정적 Qt)을 여기서 만든다. Q4(Defender·SmartScreen), Q5(자손 정리), Q6(한글 입력·배율) 중 하나라도 실패하면 **멈추고 사용자에게 알린다**. Q6은 사용자가 직접 본다. 스파이크 코드는 버리는 코드다. **Q4의 실패는 Defender가 exe를 격리·삭제·실행 차단하는 것이다.** 서명하지 않은 exe에 뜨는 SmartScreen의 "알 수 없는 게시자" 경고는 지금 exe에도 뜨므로 실패가 아니고, 지금 exe와 같은 조건(인터넷 표식을 붙여 실행)으로 나란히 비교해 지금보다 나쁘지 않으면 통과다. 코드 서명은 이 작업에 넣지 않는다 (작성자 판단) |
| Q1 `shared` | `LICENSE`(MIT)와 `vcpkg.json`, CMake 뼈대를 이 단계 첫 커밋에 넣는다 |
| Q2 `engine` | 변경 없음 |
| Q3 구글 가사 | 실제 구글 확인(G7)은 요청 수를 지금 규칙(곡당 1회, 10초 간격) 안에서만 한다. 카드에서 줄을 뽑는 스크립트는 파일 하나로 두고, `LyricsCardParser`의 지금 시험을 같은 이름·같은 고정 HTML·같은 기대값으로 옮기되 **숨긴 WebView2에 고정 HTML을 띄워 그 스크립트를 돌리는 시험**으로 만든다(작성자 판단). 이 시험은 WebView2 런타임이 있어야 하므로 따로 묶어 런타임이 없으면 건너뛰고, 네트워크는 쓰지 않는다. Node 의존은 남기지 않는다. 이 부분은 무작위 대조에서 뺀다 |
| Q4 화면 | **플레이리스트 기능(§5)을 여기서 넣는다.** 정보 창(§6)도 여기서 넣는다 |
| Q5 진단 | 변경 없음 |
| Q6 포장 | 정적 exe라서 "뒤에 붙여 풀기"는 없다. `package-exe.bat`은 CMake 릴리스 빌드를 돌려 `dist\xGetSongs.exe`를 내는 것으로 바꾼다 |
| Q7 정리 | **Q1~Q6 관문 통과만으로 시작하지 않는다. 사용자가 `dist\xGetSongs.exe`(Qt 판)를 자기 PC에서 써 보고 지워도 된다고 말한 뒤에 시작한다**(작성자 판단). 옛 코드와 Gradle·Cargo·npm 설정 제거, README를 Qt 기준으로 다시 쓴다(빌드 방법, 쓴 Qt 버전, 정적 빌드 옵션 포함) |

- 단계마다 계획서(`docs/superpowers/plans/`)를 따로 쓰고, 끝나면 보고서(`docs/superpowers/specs/…-report.md`)를 남긴다(지금까지의 방식). 첫 계획서는 Q0만 다룬다. Q0의 결과가 뒤 단계의 전제를 바꿀 수 있기 때문이다.
- 단계마다 `main`에 커밋한다. push는 그때마다 사용자에게 묻는다.
- 화면에 창이나 상자를 띄우는 점검은 돌리기 전에 사용자에게 알린다.
- Gradle을 돌릴 일이 있으면(대조 도구 등) `--no-daemon`으로 돌린다.

**대조 (Q1, Q2).** 지금 Kotlin 구현이 정답이다. `shell/tools/differential`이 Kotlin과 TS를 대조한 방식으로, 무작위 입력을 Kotlin과 C++에 넣어 결과가 다른 것이 0개인지 본다. 대상은 최소한 입력 판별, 제목 파싱, 파일명 만들기, 가사 구역 추출, 로그 가리기, yt-dlp 출력 파싱, LRCLIB 매칭이다. 정규식은 `QRegularExpression`(PCRE2)과 Kotlin의 차이를 이 대조로 잡는다.

## 5. 자체 플레이리스트

### 5.1 무엇인가

앱이 갖고 있는 "이름 + YouTube 재생목록 ID"의 목록이다. 사용자는 목록에서 하나를 골라 주소 입력란을 채우고, 그 뒤는 지금 흐름(조회 → 다운로드) 그대로다.

### 5.2 화면 (사용자 결정: 시안 B)

- 주소 입력란 **왼쪽**에 `플레이리스트 ▾` 버튼을 둔다. 누르면 메뉴가 펼쳐진다.
- 메뉴에는 목록의 항목이 순서대로 이름으로 나오고, 구분선 아래에 `목록 관리…`가 있다. 목록이 비어 있으면 항목 자리에 눌리지 않는 `(목록 없음)`이 나온다.
- **선택:** 항목을 고르면 그 재생목록 ID가 주소 입력란에 들어간다. 조회는 자동으로 누르지 않는다(작성자 판단: 사용자가 `조회`를 누른다. 지금 입력란이 입력을 받아 주지 않는 상태(작업 중 등)이면 버튼도 같이 꺼진다).
- **`목록 관리…` 대화상자:** 왼쪽에 목록, 오른쪽에 `추가`, `수정`, `삭제`, `위로`, `아래로`, `초기화` 버튼, 아래에 `닫기`.
  - `추가` / `수정`: 이름과 "재생목록 ID 또는 주소" 두 칸. 주소를 넣으면 재생목록 ID를 뽑아 저장한다(지금의 입력 판별 규칙을 쓴다). 영상 1개의 주소처럼 재생목록이 아닌 입력, 빈 이름, 이미 목록에 있는 ID는 받지 않고 이유를 칸 아래에 보여 준다.
  - `삭제`: 확인을 묻고 지운다.
  - `위로` / `아래로`: 순서를 바꾼다 (작성자 판단으로 더한 것).
  - `초기화`: §5.4.
  - 바뀔 때마다 바로 파일에 저장한다. 따로 "저장" 버튼은 없다.

### 5.3 저장

- 파일: `%APPDATA%\xGetSongs\playlists.json` (작성자 판단: `settings.json`과 따로 둔다).
- 형식: `{ "version": 1, "playlists": [ { "name": "최신 가요", "pid": "PL…" } ] }`. 배열의 순서가 화면의 순서다.
- 파일이 없으면 빈 목록이다. **첫 실행에 자동으로 원격을 읽지 않는다**(작성자 판단: 사용자가 `초기화`를 눌렀을 때만 네트워크를 쓴다).
- 파일이 깨져 읽을 수 없으면 빈 목록으로 시작하되, 깨진 파일은 덮어쓰기 전에 `playlists.json.bad`로 옮겨 둔다. 쓰기는 임시 파일에 쓴 뒤 바꿔치기한다(`QSaveFile`).

### 5.4 초기화 = 합치기 (사용자 결정)

`초기화`는 목록을 덮어쓰지 않는다. **원격 목록을 받아 중복을 빼고 지금 목록에 합친다.**

1. `https://www.gtcsoft.kr/remote_config/cherry_music_rc.json`을 받는다.
2. 그 안 `values.music_video_playlists_url_ko`와 `values.music_video_playlists_url_en`이 가리키는 두 JSON을 받는다. 각각 `{ "playlists": [ { "sn", "name", "pid", "is_free" } ] }` 형식이다.
3. 한국어 목록을 `sn` 순으로, 이어서 영어 목록을 `sn` 순으로 늘어놓는다.
4. 앞에서부터 하나씩 보며, 그 `pid`가 지금 목록(과 이번에 이미 더한 것)에 없으면 목록 **끝에** 더한다. 있으면 건너뛴다.
5. 끝나면 `N개를 더했습니다 (이미 있는 것 M개)`를 대화상자에 보여 준다.

작성자 판단으로 채운 규칙(사용자에게 미리 말했고 반대가 없었다):

- 중복의 기준은 `pid`가 같은 것이다(대소문자까지 같아야 같다). 이름은 보지 않는다.
- 이미 있는 항목은 이름도 순서도 건드리지 않는다. 사용자가 고친 이름과 직접 더한 항목은 그대로 남는다.
- 사용자가 지운 항목도 원격에 있으면 초기화 때 다시 들어온다.
- 두 언어 목록에 같은 `pid`가 있으면 먼저 본 한국어 이름만 남는다.
- `sn`은 정렬에만 쓰고 저장하지 않는다. `is_free`는 쓰지 않는다. 원격 설정의 다른 값(광고, 버전 등)은 읽지 않는다.

### 5.5 원격을 읽는 규칙 (작성자 판단)

- `QNetworkAccessManager`로 GET, HTTPS만 허용한다(설정 안의 두 URL이 `https://`가 아니면 그 URL은 실패로 본다). 리다이렉트는 HTTPS끼리만 따른다. 요청마다 제한 시간 15초, 응답 크기 1MB까지.
- 요청에 사용자나 PC를 알 수 있는 정보를 넣지 않는다.
- 원격 설정 JSON에는 `"//키"` 형태의 주석용 키가 섞여 있다. 유효한 JSON이므로 그대로 파싱하고 필요한 두 키만 읽는다.
- URL 값이 빈 문자열이거나 키가 없으면 그 언어는 빈 목록으로 본다(실패가 아니다).
- 받은 항목은 믿지 않는 데이터로 다룬다: `name`은 앞뒤 공백을 떼고 제어 문자를 지우며 100자까지만 쓰고, 비면 그 항목을 버린다. `pid`는 직접 추가할 때와 같은 재생목록 ID 검사를 통과해야 하고, 아니면 그 항목을 버린다. 버린 항목 수는 로그에 남긴다(이름과 ID는 남기지 않는다).
- **실패 처리:** 원격 설정을 받지 못하거나 파싱하지 못하면 목록을 바꾸지 않고 오류를 보여 준다. 두 언어 중 하나만 실패하면 받은 쪽만 합치고 `영어 목록을 받지 못했습니다`처럼 어느 쪽이 실패했는지 함께 보여 준다.
- 받는 동안 대화상자의 버튼을 끄고 `받는 중…`을 보여 주며, 대화상자를 닫으면 요청을 취소한다. 화면은 멈추지 않는다(비동기).

### 5.6 시험

- 합치기, 검증, 파일 읽기·쓰기, 추가·수정 입력 검사는 위젯과 분리해 Qt Test로 시험한다. 네트워크는 가짜 응답으로 바꿀 수 있게 한다(실제 gtcsoft.kr을 부르는 것은 손으로 하는 확인 1회뿐).
- 시험할 경우: 빈 목록에 합치기, 일부 겹침, 전부 겹침, 두 언어에 겹치는 `pid`, 한쪽 URL 실패, 설정 실패, 빈 URL, 잘못된 항목 섞임, 깨진 파일, `sn` 순서가 뒤섞인 입력.

## 6. 오픈 소스 공개에 필요한 것

- `LICENSE`: MIT. 저작권자 표기는 `gomtos`(git 사용자 이름)로 한다 (작성자 판단: 다른 이름을 원하면 바꾼다).
- 정보 창(메뉴나 버튼 하나로 여는 작은 대화상자): 앱 이름과 버전, MIT 라이선스, Qt를 LGPLv3로 쓴다는 사실과 Qt 버전, Qt 소스를 받는 곳, WebView2 SDK 고지. LGPLv3·GPLv3 전문은 저장소의 `THIRD-PARTY-NOTICES`(또는 같은 역할의 파일)에 두고 정보 창에서 가리킨다.
- README: 소스에서 빌드하는 방법(vcpkg, triplet, CMake preset, Qt 버전), 릴리스 exe와 커밋을 태그로 맞춘다는 규칙.

- 구글 가사는 유지하므로 README의 "개인 용도" 주의와 구글 약관 설명은 그대로 둔다.
- 저장소를 실제로 공개로 바꾸는 일과 릴리스 올리기는 이 작업에 넣지 않는다(사용자가 한다).

## 7. 만드는 쪽에 맡기는 것

- `qt/core` 안의 클래스 나누기와 이름. 지금 Kotlin 파일 구성을 따라도 되고 Qt에 맞게 바꿔도 된다. 단 테스트 이름은 지금 것과 맞춘다.
- 동시 다운로드와 취소를 무엇으로 짤지(`QThreadPool`, 프로세스별 `QProcess` + 시그널 등). 지켜야 할 것은 결과다: 동시 수(코어의 70%, 최소 1), 곡별 취소, 취소 시 자손까지 5초 안에 정리, 가사 검색의 쉬는 시간과 간격 규칙.
- 로거 구현(자체 회전 로거 또는 라이브러리), 멈춤 감시와 미니덤프의 구체적인 모양. 지켜야 할 것은 분석 문서 Q5 관문이다.
- vcpkg를 어디에 둘지(저장소 밖 권장), Qt 기능 플래그, 위젯 스타일(QSS)의 세부.
- 플레이리스트 메뉴와 대화상자의 세부 배치와 문구(§5.2의 동작은 지킨다).

## 8. 알려진 위험

- 분석 문서 §5의 위험이 그대로다. 특히 재작성 규모(테스트 약 1만 7천 줄 이식)와 동시성·취소의 회귀.
- 정적 Qt 빌드는 처음 한 번에 수십 분~수 시간과 디스크 수 GB가 든다.
- 크기(10~18MB)와 시작 시간(1초 미만)은 추정이다. Q0에서 처음 측정한다.
- `www.gtcsoft.kr`의 설정 파일은 다른 앱(cherry music)의 원격 설정이다. 키 이름이나 형식이 바뀌면 `초기화`만 실패하고 나머지 기능은 영향이 없다.
