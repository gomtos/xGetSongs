# xGetSongs

YouTube 재생목록 ID를 입력하면 목록의 모든 영상에서 오디오를 추출해 mp3로 저장하고, 영상 주소 1개를 입력하면 그 영상의 오디오만 mp3로 저장하는 Windows 데스크톱 앱입니다. 나중에 웹으로 옮길 수 있게 설계했습니다.

파일명 형식: `{순위번호 001~999} {가수명} - {제목}.mp3`

예: `001 소연 (SOYEON) - 퇴사할게여 (Narr. 기안84).mp3`

앱의 "파일명에 순번 포함" 옵션을 끄면 `{가수명} - {제목}.mp3`로 저장합니다(기본은 켜짐이고, ID3 트랙 번호는 옵션과 상관없이 순위입니다). 순번이 없으면 한 재생목록에서 같은 가수와 제목의 영상이 같은 파일명이 될 수 있어서, "기존 파일 덮어쓰기"가 꺼져 있으면 하나만 저장하고 나머지는 건너뛰며 켜져 있으면 마지막에 끝난 것으로 덮어씁니다.

설계 문서: [docs/superpowers/specs/2026-10-04-xgetsongs-design.md](docs/superpowers/specs/2026-10-04-xgetsongs-design.md)

## 저장 위치

- 재생목록: 출력 폴더 안에 재생목록 이름의 폴더를 만들어 그 안에 저장합니다. 예: `D:\Music\내 재생목록\001 가수 - 제목.mp3`. 폴더 이름의 금지 문자(`\ / : * ? " < > |`)는 전각 문자로 바꾸고 80자로 줄이며, 이름이 비면 `재생목록`을 씁니다. 같은 이름의 재생목록은 같은 폴더를 씁니다.
- 영상 1개: 폴더를 만들지 않고 출력 폴더에 바로 저장합니다.

목록을 조회하면 앱의 출력 폴더 입력란 아래에 실제 저장 위치가 표시되고, 그 줄 오른쪽의 `탐색기에서 보기` 버튼으로 그 폴더를 탐색기에서 열 수 있습니다(폴더가 아직 없으면 가장 가까운 상위 폴더를 엽니다).

## ID3 태그

받은 mp3마다 ID3v2.3 태그를 씁니다(재인코딩 없음). 값은 파일명과 달리 금지 문자를 바꾸거나 길이를 줄이지 않은 원문이고, 예외는 ffmpeg의 메타데이터 파일 형식 때문에 값 끝의 `\`를 전각 `＼`로 바꾸고 줄바꿈과 탭을 뺀 제어 문자를 지우는 것뿐입니다.

- 제목: 파싱한 제목
- 가수와 앨범 아티스트: 파싱한 가수
- 앨범: 영상 자체의 앨범(YouTube가 앨범 정보를 알고 있을 때, yt-dlp의 `album`). 없으면 재생목록 제목이고, 앨범 정보가 없는 영상 1개에는 쓰지 않습니다.
- 트랙 번호: 순위
- 주석: 영상 URL
- 가사: 영상 설명란에 `[Lyrics]`나 `가사`처럼 제목만 있는 줄이 있으면 그 아래 가사를 가사 프레임(USLT)에 씁니다. 구분선(`=====`), 링크, 저작권, 해시태그, `[Rom]`이나 `(English)` 같은 다른 구역 제목 줄 앞까지이고, 처음 나온 가사 구역 하나만 씁니다. 가사 제목이 없거나 가사가 3줄이 안 되면 설명란에서는 가사를 찾지 못한 것입니다(아래 "가사 검색"). 한글이 있으면 언어는 `kor`, 아니면 `eng`입니다.
- 커버: 썸네일의 가운데를 정사각형으로 잘라 넣습니다 (썸네일이 없으면 커버 없이 태그만 씁니다)

태그를 쓰지 못하면 그 항목은 실패로 처리되며 "실패 항목 재시도" 버튼으로 다시 받을 수 있습니다.

### 가사 검색

가사는 영상 설명란에 `[Lyrics]`나 `가사` 구역이 있으면 거기서 가져오고, 없으면(옵션이 켜져 있을 때, 기본) 공개 가사 데이터베이스 LRCLIB(lrclib.net)에서 아티스트, 제목, 앨범, 길이로 찾아 씁니다. 제목과 아티스트가 맞고 길이 차가 8초 이하인 결과만 쓰고(일본어판·라이브·리믹스 같은 다른 버전은 제외), 서비스가 응답하지 않거나 요청이 너무 많다고 하면 5분 동안 검색을 쉬며, 둘 다 못 찾으면 가사 프레임을 쓰지 않으므로 파일에 가사가 남지 않습니다. 이 검색은 아티스트, 제목, 앨범, 길이 네 값을 lrclib.net으로 보내므로, 보내고 싶지 않으면 옵션의 `가사가 없으면 인터넷에서 검색` 체크를 끄세요(그러면 설명란에 가사가 있는 곡만 가사가 들어갑니다). 가사는 저작물이므로 개인 사용 목적으로만 쓰세요.

## 필요한 것

| 도구 | 용도 | 설치 |
|---|---|---|
| JDK 21 | 빌드와 실행 | |
| yt-dlp | 영상에서 오디오 추출 | 앱의 "yt-dlp 설치" 버튼 또는 `winget install yt-dlp.yt-dlp` |
| ffmpeg | mp3 변환 | `winget install Gyan.FFmpeg` |
| Node.js 22+ 또는 Deno 2.3+ | yt-dlp가 YouTube를 읽는 데 필요 | `winget install OpenJS.NodeJS` |

앱 첫 화면 위쪽에서 세 도구의 설치 여부와 버전을 확인할 수 있습니다.

## 실행

```powershell
.\gradlew.bat :app:run
```

앱은 마지막에 쓴 옵션(출력 폴더, 덮어쓰기, 파일명에 순번 포함, 가사 인터넷 검색, 동시 다운로드 수)을 `%APPDATA%\xGetSongs\settings.json`에 저장해 두었다가 다음 실행에 되살리며, 입력한 주소와 영상 1개의 순위 번호는 기억하지 않습니다.

## 테스트

```powershell
.\gradlew.bat check                    # 전체 단위 테스트
.\gradlew.bat :engine:integrationTest  # 실제 yt-dlp, YouTube, LRCLIB를 쓰는 통합 테스트 (도구가 없거나 서비스가 응답하지 않으면 건너뜀)
```

## 문제가 생겼을 때

앱이 갑자기 사라지거나 멈췄다면 원인이 아래 파일에 남아 있을 수 있습니다.

- **로그:** `%APPDATA%\xGetSongs\logs\xgetsongs.log`. 날짜와 5MB 단위로 나뉘고(`xgetsongs.2026-10-07.0.log`처럼) 7일, 합계 50MB까지 보관합니다. 한 줄마다 바로 기록하므로 강제 종료돼도 마지막 줄이 남습니다. 시작 정보(Java, OS, 메모리, 도구 경로), 작업 시작과 옵션, 항목별 완료·건너뜀·실패와 사유, 작업 요약, 취소, 처리되지 않은 예외를 적고, 토큰, 요청 헤더, 가사, 영상 제목과 파일명은 적지 않습니다. 콘솔에는 INFO 이상만 나옵니다.
- **`ui-hang-날짜-시각.txt`:** 같은 폴더에 생기는 파일입니다. 앱 창이 5초 넘게 응답하지 않으면 모든 스레드가 그때 무엇을 하고 있었는지(창 스레드가 맨 위)와 메모리·GC 정보를 여기에 저장하고 로그에도 ERROR로 남깁니다. 멈춤이 이어지면 30초마다 같은 파일에 덧붙이고(로그에는 그때마다 한 줄만), 다시 응답하면 로그에 `UI 응답 회복 (총 N초)`를 적습니다. 파일은 20개까지 보관합니다. 절전에서 깨어난 경우처럼 확인 주기가 크게 벌어진 때는 멈춤으로 보지 않습니다.
- **`JVM 종료 시작` 줄:** 앱이 종료되기 시작할 때마다 로그에 남습니다. 창의 닫기 버튼을 눌렀다면 바로 앞에 `사용자가 창 닫기를 요청함`이 있고 `사용자가 창을 닫음`이라고 적힙니다. `외부 종료 요청`(WARN)이라고 적혀 있으면 사용자가 창을 닫지 않았는데 앱 밖에서 종료시킨 것입니다(콘솔 닫기, SIGTERM, 로그오프·시스템 종료 등). 그 줄에 종료 시점의 가동 시간, 진행 중이던 작업 수, 힙 사용량이 같이 적힙니다. 이 줄조차 없이 로그가 끊겼다면 작업 관리자의 강제 종료나 크래시처럼 종료 처리를 거치지 않은 경우입니다.

문제를 알릴 때는 가장 최근의 `xgetsongs.log`(그리고 `ui-hang-*.txt`가 있으면 그것도)를 함께 보내 주세요. 로그에는 출력 폴더와 앱 폴더의 경로가 들어 있습니다.

## 구조

```
shared/   순수 Kotlin: 입력 판별, 제목 파싱, 파일명 생성, API 모델 (웹/Wasm에서도 재사용)
engine/   yt-dlp·ffmpeg 호출, 재생목록 조회, 다운로드 작업 관리, 출력 저장소, 가사 검색(LRCLIB)
server/   Ktor API 서버 (데스크톱 앱이 127.0.0.1에 내장 실행)
app/      Compose Multiplatform UI (지금은 desktop 타깃만)
```

## 알려진 제한 (1단계)

- mp3 품질은 VBR 최고 품질(`--audio-quality 0`)로 고정입니다. ffmpeg는 PATH 또는 `%APPDATA%\xGetSongs\bin`에서 찾으며, 따로 경로를 지정하는 설정은 아직 없습니다.
- 앱을 두 번 실행하지 마세요. 시작할 때 임시 폴더(`work/`)를 비우므로 먼저 실행한 앱의 진행 중 항목이 실패할 수 있습니다.
- 이벤트 연결이 끊기면 같은 작업에 다시 붙을 수 없고 취소만 됩니다.
- 요약의 "건너뜀" 개수에는 조회 단계에서 이미 사용할 수 없던 영상이 빠집니다(목록의 각 행에는 표시됩니다).
- ffmpeg가 없으면 다운로드를 시작하기 전에 첫 항목이 실패하며 작업이 중단됩니다. 도구 패널의 안내를 먼저 확인하세요.
- `packageMsi`로 만든 설치 파일은 아직 검증하지 않았습니다. 실행은 `:app:run`을 쓰세요.

## 주의

- 내려받은 콘텐츠의 저작권과 YouTube 서비스 약관은 사용자의 책임입니다. 본인이 사용할 목적으로만 쓰세요.
- 내장 서버는 `127.0.0.1`에만 열리며, 실행할 때마다 새로 만든 토큰이 있어야 접근할 수 있습니다.
